Platform

One engine, multiple services

Capacity events from dental or healthcare systems flow into the same recovery engine. The source system remains authoritative. Vamalio ranks only candidates the source marks as eligible, checks practical feasibility, contacts them, locks the first valid acceptance and writes the confirmed result back through the configured adapter.

Production behaviour

Where a transport provider exposes an approved API, Vamalio can check capacity and request/reserve a journey. Where there is no electronic interface, it creates a human escalation task. RecoveryFlow does not decide transport entitlement.

Integration-ready architecture

How it connects

Source systems can connect through REST APIs, FHIR, HL7/interface engines, webhooks or approved file/import workflows. Each adapter implements the same small contract: fetch an event, retrieve source-eligible candidates, receive a confirmed result and optionally write the booking back.

API = request/response between systems.
Webhook = another system tells Vamalio an event happened.
Write-back = Vamalio returns the confirmed outcome to the source system.
